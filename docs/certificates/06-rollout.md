# Вывод в эксплуатацию: справки

## Этапы

### 0. Документация и решения

- Закрыть [`07-open-questions.md`](07-open-questions.md).
- Согласовать requirements / flows / tech design.

### 1. Dev (текущая цель)

- Код за feature + preview allowlist.
- В секретах / `application` / env: `app.preview.student-ids=...` (тестовые зачётки).
- Создать тестовые админ-учётки с галочками:
  - `CERTIFICATE_REVIEW_HEAD`
  - `CERTIFICATE_REVIEW_KAZAN`
  - `CERTIFICATE_REVIEW_KRASNODAR`
  (по одной или комбинированно для проверки изоляции кампусов).
- Прогнать критерии приёмки из `01-requirements.md`.
- Студенты вне allowlist **не** видят раздел.

### 2. Пилот одного филиала

- Расширить allowlist согласованным списком зачёток **или** включить флаг только для кампуса (если появится).
- Обучить сотрудников по [`03-admin-ops.md`](03-admin-ops.md).
- Следить: очередь, ошибки upload, ложные включения в отчёт после 21:00.

### 3. Три филиала

- Секции и админы на все кампусы.
- Проверить exclusion в отчётах HEAD / KAZAN / KRASNODAR.

### 4. Общий доступ

- Снять зависимость от preview (или оставить preview только для других фич).
- `app.certificates.enabled=true` (имя TBD) для всех студентов.
- Обновить ops-инструкцию и срок хранения файлов.

## Конфиг / секреты (чеклист)

- [ ] `app.preview.student-ids` — тестовые зачётки этапа 1  
- [ ] Storage path / S3 credentials (если не локальный диск)  
- [ ] Лимиты размера файла (свойства приложения)  
- [ ] Админ-учётки с нужными секциями  
- [ ] Cron отчёта по-прежнему `Europe/Moscow` 21:00  

## Откат

1. Убрать зачётки из preview / выключить флаг сертификатов → UI и API студента закрыты.
2. Секции админов можно оставить (очередь пустеет) или скрыть пункт меню флагом.
3. Уже одобренные периоды: решить, остаются ли в exclusion (предпочтительно да до конца периода) или чистятся отдельной командой — зафиксировать перед пилотом.

## Мониторинг

- Число `PENDING` старше N часов.
- Ошибки upload / 413 / 415.
- Расхождения: одобрено до 21:00, но студент в Excel отчёта (баг exclusion).
