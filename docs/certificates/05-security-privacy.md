# Безопасность и ПДн: справки

Справки (в т.ч. больничные) — чувствительные данные. Ниже — правила этапа 1.

## Доступ

| Кто | Что |
|-----|-----|
| Студент-владелец | Свои заявки и вложения; только при preview-allowlist на этапе 1 |
| Родитель | Заявки по `studentId` ребёнка из parent-сессии; тот же preview-allowlist |
| Админ с `CERTIFICATE_REVIEW_*` | Заявки **своего** кампуса и вложения |
| Остальные | Нет доступа (403/404) |

Preview-allowlist **не** замена авторизации: каждый endpoint проверяет сессию + ownership/campus + allowlist (для студента/родителя).

## Файлы

- Отдача только через API с сессией (студент или админ).
- Без публичных прямых URL в object storage (или подписанные URL с коротким TTL — если выберут S3).
- Не логировать содержимое файла; в логах — id заявки, student_id, admin id, действие.

## Аудит (желательно с этапа 1)

- Создание / отправка / отзыв заявки.
- Одобрение (с периодом) / отклонение (с причиной).
- Скачивание вложения (кто, когда, request id).

## Хранение и срок

До бизнес-решения (open questions):

- Отклонённые / отозванные — не хранить дольше необходимого (кандидаты: 30–90 дней).
- Одобренные — минимум до конца периода + разумный архив для споров.
- Удаление с диска/бакета по политике, не только soft-delete статуса.

## Сессии и CSRF

Как в текущем ЛК (cookie session студента / lk-admin). Не вводить отдельные «токены скачивания» без необходимости.

## Что не является мерой защиты

- Скрытие пункта меню без серверной проверки.
- Доверие к кампусу только с клиента.
- Интеграции с ЕМИАС (их нет) — проверка подлинности вне системы не снимает обязанности ограничить доступ к файлу в ЛК.
