# Требования: загрузка справок и согласование отсутствий

Статус: согласованный черновик этапа 1 (dev). Решения — [`07-open-questions.md`](07-open-questions.md).

## Цель

Студент или родитель загружает в ЛК справку и отправляет заявку. Сотрудник филиала после самостоятельной проверки подлинности **вне ЛК** одобряет или отклоняет. При одобрении указывает период отсутствия (полные календарные дни). Период учитывается при **следующих** сборках отчёта отсутствующих: если к моменту сборки за день `D` заявка уже одобрена с периодом, покрывающим `D`, студент не попадает в мониторинг. Уже собранный отчёт за сегодня при позднем одобрении **не переписываем**.

## Вне scope (этап 1)

- Интеграции с ЕМИАС / военкоматом / автопроверка подлинности.
- UI «проверено в ЕМИАС».
- Правка уже сформированного отчёта отсутствующих после 21:00.
- Отдельная сущность «календарь отсутствий» (период живёт на одобренной заявке).
- Выбор программы обучения на заявке.
- Публичные URL файлов без сессии.

## Роли

| Роль | Действия |
|------|----------|
| Студент (preview-allowlist) | Создать заявку, вложения, статусы, отозвать PENDING |
| Родитель (preview по зачётке ребёнка) | То же за выбранного/текущего ребёнка |
| Админ с секцией кампуса | Очередь филиала, скачать, одобрить+период / отклонить+причина |
| Супер-админ (ADMINS) | Выдавать секции при создании учёток |

## Кампусы и доступы

- `HEAD` / `KAZAN` / `KRASNODAR`
- Секции: `CERTIFICATE_REVIEW_HEAD` / `_KAZAN` / `_KRASNODAR`
- Три **отдельных** раздела админки; заявка попадает только в раздел кампуса профиля студента.
- `ABSENCE_REPORT_*` не даёт доступ к справкам автоматически.
- Кампус заявки — **из профиля**, без выбора пользователем.

## Dev-видимость

- UI/API студента и родителя — только `previewEnabled` / `app.preview.student-ids`.
- Проверка allowlist на сервере.
- Админ — по секции филиала.

## Подача заявки (студент / родитель)

1. Тип: больничный / освобождение от военкомата / **прочее**.
2. Вложения: PDF, JPG, PNG, HEIC; до **50 МБ** каждый; **до 5** файлов; период дат **не** спрашиваем.
3. Опциональный комментарий.
4. Отправка → `PENDING` → очередь админа кампуса + уведомление админу.
5. Список своих заявок; скачать свои файлы; отозвать `PENDING` → `CANCELLED`.
6. Можно параллельно подавать заявки с пересекающимися датами (даты появятся только после одобрения админом).

## Решение админа

1. Очередь только своего филиала.
2. Скачать вложение; проверка подлинности **вне ЛК**.
3. **Одобрить** → обязательные `approved_from` / `approved_to` (полные дни) → `APPROVED` + уведомление заявителю.
4. **Отклонить** → обязательная причина → `REJECTED` + причина видна заявителю + уведомление.
5. Без полей внешней проверки.

## Отчёт отсутствующих

- Cron 21:00 МСК (`app.absence-report.auto-cron`).
- При сборке за день `D` и кампус `C`: исключить студентов с `APPROVED` заявкой кампуса `C`, у которых `approved_from ≤ D ≤ approved_to`.
- Одобрение **после** старта сборки за `D`: отчёт за `D` не трогаем; исключение сработает с ближайшей будущей сборки, где день входит в период.
- Уведомления/PDF absence-notice текущего модуля не перестраиваем задним числом на этапе 1.

## Статусы

| Статус | Смысл |
|--------|--------|
| `PENDING` | На проверке |
| `APPROVED` | Одобрена, период задан админом |
| `REJECTED` | Отклонена (причина обязательна) |
| `CANCELLED` | Отозвана заявителем |

Черновик `DRAFT` — опционально; можно сразу `PENDING` после upload+submit.

## Файлы и хранение

- Upload ≤ 50 МБ; типы PDF/JPG/PNG/HEIC.
- Картинки: сжатие как фото пропуска (`normalizeForStorage`).
- PDF: как есть.
- Хранение: локальный каталог на volume (как `app.pass-photo.storage-dir`), отдельный path для справок.
- Выдача только через authenticated API.

## Уведомления

- Заявителю (студент или родитель-инициатор): одобрение (с периодом) и отклонение (с причиной).
- Админу о новой `PENDING`: **опционально** — только если в настройках справок кампуса задана почта для уведомлений; иначе только очередь в UI.

## Хранение файлов

- Картинки сжимаются как фото пропуска; PDF as-is; диск/volume.
- Удаление через **1 месяц** после отклонения, отзыва или окончания одобренного периода.

## НФТ

- Аудит решений и скачиваний.
- Ownership + campus isolation.
- Session-auth как в текущем ЛК.

## Критерии приёмки этапа 1 (dev)

1. Preview-студент и preview-родитель подают заявку с файлом; вне allowlist — отказ.
2. Админ Казани не видит заявки Краснодара/Головы.
3. Одобрение без периода невозможно; отклонение без причины невозможно.
4. Изображения на диске нормализованы; PDF без перекодирования; отказ > 50 МБ.
5. Сборка отчёта исключает студента с одобренным периодом на день `D`; поздний approve не меняет уже сохранённый отчёт за `D`.
6. Нет интеграции с ЕМИАС в коде/UI.
