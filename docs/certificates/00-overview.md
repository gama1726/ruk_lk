# Обзор: справки и оправданные отсутствия

Кратко для руководства и онбординга. Детали — в соседних файлах каталога.

## Зачем

Студент сам загружает справку в ЛК и отправляет её на согласование. Сотрудник филиала проверяет подлинность **сам во внешних системах** (ЕМИАС и т.п. — не часть ЛК), затем одобряет заявку и указывает период отсутствия. Этот период учитывается при сборке отчёта отсутствующих: при одобрении **до 21:00 МСК** студент не попадает в мониторинг на дни из справки.

## Для кого (этап 1 / dev)

- Студенты и родители — только зачётки из `app.preview.student-ids`.
- Админы — три отдельных раздела справок: Голова, Казань, Краснодар.

## Что не делаем на этапе 1

Автопроверку и интеграции с внешними базами. Правку уже собранного отчёта после 21:00. В ЛК — очередь, файл, решение, период на заявке.

## Как устроено (логика)

```text
Студент / родитель         Админ филиала              Отчёт отсутствующих
      |                          |                              |
  файл + тип ---------------> очередь кампуса                   |
  (без периода)            одобрить + период дней ------------->|
      |                     (проверка вне ЛК)                   |
      |                          |              при сборке: исключить
      v                          v              если день ∈ периода
  статусы + уведомления     аудит решения       (готовый отчёт не трогаем)
```

## Связь с текущим ЛК

- Кампусы и cutoff 21:00 — как у модуля отчётов отсутствующих.
- Preview-гейт — как у других разделов «в разработке».
- Права админов — отдельные секции, не смешивать с `ABSENCE_REPORT_*`.
